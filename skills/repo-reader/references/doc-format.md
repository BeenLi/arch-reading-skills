# 架构和使用文档契约

文件名：`<Name>-架构和使用文档.md`；写进仓库时是 `<repo>/ARCHITECTURE.md`，vault 里的同名文件是它的硬链接（见 SKILL.md 落盘规则），两者内容同一份、都遵守本契约。`<Name>` 取仓库名或项目自称（README 标题）。本文是人读的契约；`scripts/check_doc.py` 是同一契约的机器版本，两者必须一致。写完后自检：

```bash
python3 scripts/check_doc.py <doc.md> --name <Name>
```

## 头部（固定三要素）

1. 第一个非空行是引用块，一句话定位：`> 一份面向日常研发的 <Name> 说明书：解释它是什么、<两三个本仓库最关心的问题>，以及排查问题时优先看哪些源码和文档。`
2. 紧接三行元信息，每行独立成段（中间空一行；行尾不留空白，不要用行尾双空格换行，`git diff --check` 会报 trailing whitespace，校验器也会判失败）：
   - `源仓库：` remote URL；没有 remote 写"本地仓库"
   - `本次分析的本地路径：` 绝对路径（全文唯一允许出现机器专属路径的地方）；文档要提交进仓库时写 `<repo>` 占位符，公开仓库不记录机器路径
   - `本次分析的提交：` `<短 hash> <日期> <subject>`；目标不是 git 仓库时写 `无 git 仓库；最新文件 mtime <日期>`。三个标签逐字固定，不要自创标签（如“源位置”“文件版本”）。
3. 不写 frontmatter；不用 Obsidian task 语法（`- [ ]` / `- [x]`）。

## 正文 12 节

H2 编号与标题固定，`<Name>` 代入。第 6、8、11 节允许用斜杠两侧任一表述或完整表述，其余逐字一致。

| # | 标题 | 必填元素 |
|---|---|---|
| 1 | 一句话理解 `<Name>` | 三段：是什么；由哪几条主线 / 目录组成及各自职责；不是什么、核心输入输出 |
| 2 | 核心心智模型 | 表 `概念 \| 来源 \| 含义`，6–12 行，来源列写文件路径 |
| 3 | 总体架构 | 一张 Mermaid（默认 `flowchart TB`）+ `### 3.1 组件职责` 表 `组件 \| 关键文件 \| 职责` |
| 4 | 项目如何工作 | ≥ 2 个 `### 4.x` 主链路走读，按时间顺序编号步骤，每步引用文件；多角色交互可用 `sequenceDiagram` |
| 5 | 安装与启动 | 命令块只能来自 README / 脚本 / 配置文件，逐条注明出处 |
| 6 | 常用命令 / 使用指南 | 按场景分 `### 6.x` |
| 7 | 配置项与环境变量 | 表格；每项写默认值（逐字抄代码常量）与定义位置（函数名或小节，不写行号） |
| 8 | 常见使用场景 / 推荐工作流 | 编号场景，每个场景给命令或入口 |
| 9 | 源码入口索引 | 表 `想了解 \| 优先看` |
| 10 | 排错指南 | 表 `现象 \| 优先检查 \| 依据` |
| 11 | 开发者视角的模块关系 / 维护注意点 | 可含第二张 Mermaid；写耦合点、改一处要同步改哪些 |
| 12 | 已知不确定点 | 列表 ≥ 2 条；第一条固定说明"本次为静态源码分析，未执行 …"，其余为未核实或互相矛盾的地方 |

12 节之后允许 `## 附录 X. …`（例如 Obsidian 硬链接、目录约定、SKILL.md 深度解析），附录不计入编号，但同样遵守下面的通用规则。

## 通用规则

- 每个 H2 节（第 12 节除外）至少出现一个反引号包裹的仓库内路径作为来源，例如 `` `src/core/scheduler.py` ``、`` `README.md` ``，或含路径的命令 `` `python3 src/main.py --once` ``（反引号内任一个词含 `/`、以字母扩展名结尾、是 `Makefile` / `Dockerfile` / `LICENSE` 这类知名无扩展名文件或 `.gitignore` 这类点文件即可；`` `vLLM` ``、`` `1.0` ``、URL 不算）；第 5 节每个命令块前后一句话写出处。
- Mermaid 图 2–5 张（```` ```mermaid ```` 或 `~~~mermaid` 围栏，列表里缩进的也算；放在更长围栏里的被引用示例不算），每张图下方一段自然段解释它表达的结构；按 `~/.claude/skills/_shared/references/mermaid-rules.md` 渲染、看图、重排。
- 正文 250–800 行；中文叙述，标识符、命令、路径保持英文原样。
- 除头部"本地路径"行外，正文不出现 `/Users/…`、`/home/…`、`C:\…` 这类机器专属绝对路径；需要时写 `<repo>`、`<vault>` 占位符。
- 不杜撰命令、参数、文件；读不到、没把握的写进第 12 节，不要写成肯定句。
- 代码块（``` 或 ~~~）里的内容不参与章节、表头、步骤和 task 语法检查，可以放心引用 Markdown 骨架；但代码块里的机器路径仍会被判失败。
- 第 2、3、9、10 节的表头前几列逐字照抄，末尾可以追加列（例如 `| 现象 | 优先检查 | 依据 | 备注 |`）。
- 表格单元格里的 `|` 写成 `\|`。
