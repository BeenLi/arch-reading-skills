# 笔记质量详细规范

## 公式质量检查

> 教训（DreamerV1 事件）: 公式不仅要"有"，还要"对"。

### 5 类必检公式错误

| # | 错误类型 | 示例 | 检查方法 |
|---|---------|------|---------|
| 1 | **变量冲突** | $v(s_\tau) = \sum_\tau r_\tau$（$\tau$ 既是自由变量又是求和变量） | 确保 bound variable 和 free variable 不同名 |
| 2 | **公式-文本不一致** | 文字说 "stop-gradient" 但公式里没写 $\operatorname{sg}(\cdot)$ | 文字描述的性质必须在公式中体现 |
| 3 | **符号约定不一致** | 正文用 $p$ 表示后验，公式用 $q$ | 全文统一使用原论文符号约定 |
| 4 | **上下标/求和范围错误** | $\sum_{n=1}^{H}$ 写成 $\sum_{n=1}^{H-1}$ | 逐字核对原论文 |
| 5 | **缺少关键算子** | 省略 $\mathbb{E}$、$\nabla$、stop-gradient 等 | 确认所有算子完整 |

### Obsidian MathJax 适配

1. **避免超长单行公式**（>80 字符拆分为 `aligned` 块）
2. **`$$` 块前后必须有空行**（否则不渲染）
3. 安全命令：`\operatorname{}`, `\text{}`, `\begin{aligned}`, `\underbrace{}`
4. `\Big`, `\bigg` 优于 `\left`/`\right` 处理大括号嵌套

### 公式自检清单

- 变量名与上下文一致？无冲突？
- 文字描述的数学性质在公式中体现？
- 求和/积分范围与原论文一致？
- 长公式已拆分？
- `$$` 前后有空行？

## 表格提取规范

**必须提取论文中的所有表格（ALL Tables）**，完整保留所有行列数据：

```markdown
**Table X: {表格标题}**

| Method | Metric1 | Metric2 |
|--------|---------|---------|
| Baseline | 45.2 | 78.3 |
| **Ours** | **52.1** | **85.6** |

用 2-4 句自然段解读表格：说明它在论文论证链中的作用、关键趋势或定量证据，以及它支撑的设计或结论。
```

## 图片提取规范

**每篇论文笔记必须包含所有 Figure**，一张都不能漏。

同时检查**项目主页**上的额外图片（如预训练流程图、消融可视化等）。

每张图片必须包含：
1. **图注标题** - 写在图片引用的题注/alt 文本中，例如 `![Figure X: 英文标题 / 中文标题](...)`
2. **图片** - 外链优先（arXiv HTML、项目主页等），找不到再本地
3. **自然段解读** - 解释图片在论文论证链中的作用、关键趋势或定量证据，以及它支撑的设计或结论；不要保留填空式模板标签

题注里引用文献时写成 `转引自 文献 174`，不要写 `[174]`：`![[…|…]]` 嵌入的题注里一旦出现方括号，Obsidian 会在第一个 `]]` 处截断题注并多出一个 `]`。

如果图源是本地 PDF，必须从 PDF 裁切图片并存放到笔记同目录下的 `00_assets/<note-name>_<原图片名>`；笔记中使用 `![[00_assets/<note-name>_<原图片名>]]`。`note-name ≤ 48 字符` 时直接用 `<note-name>_`；note-name 太长时使用 `截断前 40 字符 + 8 位 hash`，形如 `VeryLongNoteNamePrefix_xxxxxxxx_figure.png`。

### Obsidian 大纲层级规范

图表完整性不能以污染 Obsidian 大纲为代价。

- 普通 Figure / Table 不要默认写成 H3 图表标题。
- 图片应嵌入它支撑的语义小节下，图片标题写进图片引用的题注/alt 文本，不要在图片上方单独写 `**Figure ...**` 标题；Table 标题仍可用表格上方的加粗行。
- `###` 只给真实语义结构使用，例如 `### 动机实验`、`### Encoder 消融`、`### SLO 适配结果`、`### 附录补充图`。
- 多张低优先级附录图可以合并在一个语义小节下，逐张用图片题注/alt 标清 Figure 标题。
- 如果某张图本身就是一个核心机制小节的唯一内容，先给机制小节起语义标题，再用图片题注/alt 标清 Figure 标题。

### Obsidian Tasks 规范

论文笔记正文不要使用 task list 语法。

- 不要输出 `- [ ]` 或 `- [x]`。
- `复现` 中的核查内容使用 `### 复现核查表`，优先写成 `项目 / 结论 / 证据或缺口` 三列表格。
- 过程性步骤、风险项、后续工作都写成普通 bullet 或表格；只有用户明确要求创建任务时才使用 task 语法。

## 笔记内跳转

正文提到 Figure / Table / 公式 / Insight / 机制 / 贡献时一律写成 Obsidian 跳转链接，不写裸文字。依据 Obsidian 官方规则：

- 同笔记标题链接 `[[#标题|显示文字]]`；标题里避免 ASCII 的 `# | ^ : %%`，模板用全角 `：`，不受影响。
- 块引用 `[[#^id|显示文字]]`。id 只能用拉丁字母、数字、连字符。单行段落（含只有一张图片的行）在行尾加 ` ^id`；表格、列表、callout 等多行块把 `^id` 单独放一行，前后各空一行；列表的单个条目可以直接在条目末尾加。表格内部的单行不能被链接。
- `$$` 公式块后挂 id 的行为官方未定义，所以公式锚点挂在公式下方的解释段末尾，跳转落点一样。

| 对象 | 定义处写法 | 引用处写法 |
|---|---|---|
| Figure | `![Figure 3: …](url) ^fig3`；本地嵌入 `![[00_assets/…\|Figure 3: …]] ^fig3`；子图 `^fig8a` | `[[#^fig3\|Figure 3]]` |
| Table | 表格结束后空一行，单独一行 `^tab1`，再空一行 | `[[#^tab1\|Table 1]]` |
| 笔记自建表格（组件表、映射表等） | 同上，id 用语义名如 `^tab-components` | `[[#^tab-components\|组件表]]` |
| 公式 | 公式下方解释段末尾 ` ^eq-ttft`（语义名） | `[[#^eq-ttft\|TTFT 分解式]]` |
| Insight / 机制 / 任何章节 | 标题本身，不加标记 | `[[#Insight 2：…\|Insight 2]]`、`[[#机制1：…\|机制1]]` |
| 核心贡献条目 | 列表项末尾 ` ^contrib-1` | `[[#^contrib-1\|贡献1]]` |
| agent 自画的图（diagram-design / draw.io / 退回的 Mermaid） | PNG 嵌入行在行尾加 ` ^diag-arch`；退回 Mermaid 时代码块之后单独一行 `^diag-arch`，前后空行；执行流全局图用 `^diag-flow`、评测平台图用 `^diag-platform` | `[[#^diag-arch\|架构图]]`、`[[#^diag-flow\|执行流图]]` |

规则：

1. 每个对象只在首次出现处挂一个 id，id 全文唯一，全小写。
2. 标题链接的别名用短名（`Insight 2`、`机制1`），标题部分必须与目标标题逐字一致，否则 Obsidian 无法跳转。
3. 表格单元格里的 wikilink 别名分隔符写成 `\|`（如 `[[#机制1：X\|机制1]]`），否则会切坏 Markdown 表格；正文段落里照常写 `|`。
4. 笔记和概念笔记都写完后，运行 `scripts/check_note_links.py <笔记>` 复查：它报告断开的标题 / 块链接、重复锚点、找不到的 `[[概念]]` 或嵌入、表格行内未转义的 `|`，以及漏写链接的裸引用（含 “Figure 3–5” 这类范围和链接后剩下的裸尾巴）。修到输出 `OK` 为止。

## 提取完整性自检清单

**零遗漏原则：所有图、所有公式、所有表格必须全部出现在笔记中。**

图片：
- 论文有多少张 Figure？笔记中全部包含？
- 普通 Figure 的标题是否写进图片题注/alt，而不是 H3 大纲标题或图片上方的独立加粗行？
- 外链 URL 对应正确 Figure？
- 无外链的已下载或从 PDF 裁切到本地 `00_assets/`，并按 `<note-name>_<原图片名>` / 长 note-name hash 规则用 `![[]]` 嵌入？
- 项目主页有额外图片？已补充？

公式：
- 论文有多少个公式？笔记中全部包含？
- 变量名一致？无冲突？
- 长公式已拆分适配 Obsidian？

表格：
- 论文有多少张 Table？笔记中全部包含？所有行完整？
- 普通 Table 是否用表格上方的标题行，而不是 H3 大纲标题？
